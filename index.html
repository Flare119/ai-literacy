LLM — Large Language Model
ChatGPT, Claude, Gemini, GPT-4 đều là LLM
Nền tảng

Bản chất

Model được train trên hàng tỷ trang text. Nó học cách "từ này → từ tiếp theo nào có xác suất cao nhất". Không có ý thức, không hiểu — chỉ dự đoán cực kỳ giỏi.

Như 1 biên kịch đã đọc mọi kịch bản trên đời. Khi bạn cho nó 1 đoạn mở đầu, nó viết tiếp theo pattern đã học. Không sáng tạo — nhưng recombine cực hay.

Tại sao quan trọng

  • ChatGPT / GPT-4 / GPT-5 — OpenAI, mạnh nhất ở conversational + image edit
  • Claude — Anthropic, mạnh reasoning + code + văn bản dài
  • Gemini — Google, multimodal (text + image + video)

Khi nào dùng

Viết brief, brainstorm, dịch, phân tích, code, lên kế hoạch — mọi thứ liên quan text/logic.

Dùng Claude để viết prompt, phân tích storyboard, quản lý kiến thức dự án — đó là LLM at work.
Diffusion Model
FLUX, Midjourney, Stable Diffusion, DALL-E đều là diffusion
Nền tảng

Bản chất

Model học cách "khử noise". Training: lấy ảnh đẹp → thêm noise dần cho đến khi thành static TV → model học cách đi ngược lại (từ noise → ảnh). Generation: bắt đầu từ noise ngẫu nhiên → dần dần "lọc" thành hình theo prompt.

Như sculptor bắt đầu với khối đá (noise) rồi đục dần ra hình. Prompt là brief — "tôi muốn tượng người phụ nữ cầm hoa". Model đục dần cho đến khi ra hình.

Tại sao quan trọng

  • Mọi AI image gen (FLUX, NB2, Midjourney) đều dựa trên diffusion
  • AI video gen (Kling, Runway, Veo) = diffusion áp dụng cho video frames
  • Hiểu diffusion → hiểu tại sao AI "hallucinate" (thêm ngón tay, text sai) — vì nó "đoán" pixel, không "vẽ" có chủ đích

Giới hạn gốc

  • Không hiểu "ý nghĩa" — chỉ biết pattern pixel nào hay đi cùng nhau
  • Small objects (S Pen, chữ nhỏ) = khó control vì model nhìn big picture trước
  • Hands/fingers = vùng có nhiều variation trong training data → model confused
Trong 1 dự án TVC: bút stylus bị sai hình dáng liên tục = diffusion model không có "concept" về vật thể cụ thể, nó chỉ biết "vật dài nhỏ trong tay" → approximate.
Transformer Architecture
Kiến trúc nền tảng đằng sau MỌI AI model hiện đại
Nền tảng

Bản chất

Transformer = cách organize thông tin bằng "attention" — model học được "từ/pixel này liên quan đến từ/pixel kia ở đâu trong input". Phát minh 2017 bởi Google ("Attention Is All You Need").

Như đạo diễn xem toàn bộ footage cùng lúc và biết "frame này liên quan frame kia" thay vì xem tuần tự. Attention = khả năng nhìn mọi thứ cùng lúc và tìm connections.

Tại sao EP cần biết

  • Context window — model chỉ "nhìn" được X tokens cùng lúc (GPT-4: 128K, Claude: 200K). Quá dài → quên đầu.
  • Attention — lý do prompt dài quá model bỏ qua details. Nó "chú ý" vào phần nổi bật nhất.
  • Không cần biết math — chỉ cần hiểu: model có giới hạn "bao nhiêu thứ nhìn cùng lúc"
Training vs Fine-tuning vs Inference
3 giai đoạn của AI model — từ "sinh ra" đến "đi làm"
Nền tảng

3 giai đoạn

  • Training (Pre-training) — Dạy model từ zero. Tốn $10M-$100M+, hàng tháng, hàng ngàn GPU. Chỉ big tech làm (OpenAI, Google, Anthropic).
  • Fine-tuning — Lấy model có sẵn, dạy thêm domain cụ thể. Rẻ hơn ($100-$10K), vài giờ-ngày. Ví dụ: Soul ID trên Higgsfield = fine-tune model nhận diện mặt bạn.
  • Inference — Model đã train xong, giờ "đi làm". Mỗi lần bạn gen ảnh/video = 1 inference call. Tốn credit.
Training = đào tạo DP 4 năm đại học. Fine-tuning = DP học thêm style quay xe hơi. Inference = DP đi quay TVC thật — mỗi ngày quay = tốn tiền.

Thuật ngữ liên quan

  • LoRA — Low-Rank Adaptation. Cách fine-tune "nhẹ" — chỉ điều chỉnh 1-5% params thay vì toàn bộ model. Rẻ, nhanh. Soul ID dùng kỹ thuật tương tự.
  • Checkpoint — "Snapshot" của model tại thời điểm training. Như save game.
  • Weights — Các con số bên trong model (hàng tỷ). Đây là "kiến thức" của AI.
Train Soul ID cho nhân vật trong TVC = fine-tuning. Mỗi lần gen video = inference. Credits tốn = chi phí inference.
Multimodal AI
Model hiểu nhiều loại input: text + image + video + audio
Nền tảng

Bản chất

Model "cũ" chỉ hiểu 1 loại (text HOẶC image). Multimodal = hiểu nhiều loại cùng lúc. GPT-4o, Gemini 2.5, Claude nhìn ảnh + đọc text + nghe audio.

Tại sao quan trọng cho Production

  • Vision — Model nhìn board/frame → hiểu composition, đề xuất prompt
  • Image generation — Input text → output image (FLUX, NB2, GPT Image)
  • Video generation — Input image+text → output video (Kling, Veo, Seedance)
  • Audio — Veo 3.1 gen video CÓ audio. Sắp tới audio sẽ standard.
Gửi storyboard cho AI → nó "nhìn" hình + đọc mô tả → viết prompt. Đó là multimodal: image understanding + text generation.
Tokens & Context Window
Đơn vị đo "dung lượng" của AI — tại sao nó quên
Nền tảng

Bản chất

  • Token ≈ 3/4 từ English, ≈ 1/2 từ tiếng Việt. "Xin chào" = 2-3 tokens.
  • Context window = bao nhiêu tokens model "nhìn" cùng lúc. Claude: 200K tokens ≈ 150K từ ≈ 300 trang sách.
  • Input tokens = bạn gửi vào (prompt + context). Output tokens = AI trả lời.

Tại sao quan trọng

  • Prompt quá dài → model "chú ý" phần đầu + phần cuối, bỏ qua giữa
  • Credit/cost tính theo tokens — prompt dài = tốn hơn
  • Image/video prompt: ngắn gọn + rõ ràng luôn tốt hơn dài dòng
Context window = "trí nhớ ngắn hạn" của AI. Giống DP chỉ nhớ được brief 5 trang — brief 50 trang sẽ bỏ sót detail.
API — Application Programming Interface
"Cửa sau" để phần mềm nói chuyện với nhau
Nền tảng

Bản chất

API = giao thức giao tiếp giữa 2 phần mềm. Thay vì mở web UI bấm nút, bạn gửi lệnh trực tiếp cho server.

Web UI Higgsfield = đến quán order trực tiếp. API/MCP = gọi điện order delivery. Cùng món, khác cách gọi. API nhanh hơn, tự động được, nhưng ít options hơn (như MCP không có unlimited toggle).

Thuật ngữ liên quan

  • Endpoint — "Địa chỉ" cụ thể để gửi request. VD: `/generate_image`
  • Token (auth) — "Chìa khóa" để API biết bạn là ai. Khác token (text unit).
  • Rate limit — Server giới hạn bao nhiêu request/phút
  • Webhook — Server "gọi lại" bạn khi xong (thay vì bạn hỏi liên tục)
Ví dụ: gọi API gen video = 1 API call. Auth token hết hạn 24h → phải re-auth. Rate limit = chỉ được X requests/phút.
Open Source vs Closed Source vs Open Weight
Ai sở hữu AI? Tại sao có model miễn phí?
Nền tảng

3 loại

  • Closed Source — Không ai thấy bên trong. Chỉ dùng qua API/web. GPT-4, Claude, Gemini, Kling, Runway.
  • Open Weight — Công bố weights (model file) để ai cũng download chạy. Nhưng KHÔNG cho biết training data/code. LLaMA (Meta), Flux, Stable Diffusion.
  • Open Source — Công bố TẤT CẢ: code + data + weights. Hiếm. Mistral (một phần).

Tại sao quan trọng

  • Open weight = chạy trên máy riêng → không tốn API cost, không bị rate limit
  • Closed source = quality cao hơn (thường), nhưng phụ thuộc vendor
  • FLUX = open weight → Higgsfield host nó cho bạn dùng, hoặc tự host được

AI Production

Cách AI image/video models hoạt động — hiểu để prompt tốt hơn và biết giới hạn.

txt2img vs img2img vs img2vid
3 pipeline chính trong AI visual generation
Production

3 loại generation

  • txt2img (Text-to-Image) — Chỉ dùng text prompt → gen ảnh. FLUX, Midjourney, NB2. Control ít nhất.
  • img2img (Image-to-Image) — Input ảnh + prompt → edit/transform ảnh. Kontext, GPT Image. Control nhiều hơn.
  • img2vid (Image-to-Video) — Input 1-2 frame + prompt → gen video clip. Kling, Veo, Seedance. Start/end frame = keyframes.
txt2img = brief miệng cho artist (ít control). img2img = đưa reference + brief (nhiều control hơn). img2vid = đưa storyboard frame + brief cho animator.

Production workflow

Gen character sheet (txt2img/img2img) → dùng làm start/end frame → gen video (img2vid). Đó là pipeline đang dùng.

Ví dụ: ref nhân vật (img2img qua Kontext/GPT Image) → character sheet → start/end frame cho Kling 3.0 (img2vid).
Frame Interpolation & Motion
Tại sao AI video gen bị tay di chuyển dù prompt nói "freeze"
Production

Bản chất

Khi cho start frame (A) + end frame (B) khác pose → model PHẢI interpolate (tạo frames giữa A→B). Nếu A = tay ở trên, B = tay ở dưới → model buộc phải animate tay di chuyển.

Quy tắc

  • "Freeze" trong prompt = gợi ý, KHÔNG phải lệnh. Model vẫn interpolate nếu A≠B.
  • Muốn body freeze → start và end frame phải CÙNG body pose, chỉ khác camera angle/background.
  • Muốn chỉ camera move → cùng pose + khác framing.
Ví dụ: prompt "hands remain still" nhưng start frame = tay viết, end frame = tay cầm phone → Kling interpolate tay di chuyển. Solution: dùng cùng hand pose cả 2 frame.
Character Consistency & Identity
Tại sao mặt bị đổi giữa các shot — và cách fix
Production

Vấn đề

Mỗi lần gen = bắt đầu từ noise MỚI → kết quả khác nhau dù cùng prompt. Face drift = mặt thay đổi qua các shots.

Giải pháp hiện tại

  • Soul ID / Character Reference — Upload 5-20 ảnh mặt → model "nhớ" khuôn mặt. Higgsfield Soul ID, Kling Character Ref.
  • img2img edit — Giữ nguyên ảnh gốc, chỉ edit 1 phần (Kontext, GPT Image). Consistency tốt hơn vì không gen từ zero.
  • Seed — Con số random ban đầu. Cùng seed + cùng prompt = cùng kết quả (lý thuyết). Thực tế: hữu ích nhưng không 100%.
  • Face swap post — Gen video xong → swap face bằng tool khác (insightface, roop). Brute force nhưng hiệu quả.
Thực tế: Kontext đổi outfit + angle + bg cùng lúc → face drift nghiêm trọng (7 tấm 7 mặt khác nhau). GPT Image edit từng bước nhỏ → giữ mặt tốt hơn.
CFG Scale, Steps, Seed
Các "nút vặn" control output — khi nào cần quan tâm
Production

3 params chính

  • CFG Scale (Guidance) — Model "nghe" prompt bao nhiêu. Thấp (1-5) = tự do, sáng tạo. Cao (7-15) = bám sát prompt nhưng có thể "cứng".
  • Steps — Bao nhiêu bước "khử noise". Nhiều hơn = chi tiết hơn nhưng chậm hơn. 20-30 là standard.
  • Seed — Số random khởi đầu. Cùng seed = cùng "điểm bắt đầu" → output gần giống.
CFG = mức độ DP nghe brief (thấp = "em thích thì quay", cao = "quay đúng y brief"). Steps = bao nhiêu take. Seed = location (cùng location = cùng vibe).

Khi nào EP cần biết

Hầu hết platform (Kling, Higgsfield web) đã set tối ưu. Chỉ cần biết khi debug: "tại sao output quá generic?" → có thể CFG quá cao. "Tại sao không giống prompt?" → CFG quá thấp.

AI Video Models — Cách chúng hoạt động
Kling, Veo, Runway, Seedance — khác nhau ở đâu
Production

Cơ chế chung

Video = chuỗi frames. AI gen video bằng 2 cách:

  • Temporal diffusion — Gen từng frame nhưng có "attention" liên kết giữa các frame → motion mượt. Kling, Runway dùng cách này.
  • Autoregressive — Gen frame 1, dựa vào frame 1 gen frame 2, rồi frame 3... Consistent hơn nhưng chậm hơn.

So sánh nhanh (mid-2026)

  • Kling 3.0 — Motion mạnh, camera moves tốt, face adherence OK. 5-10s. Yếu: small objects.
  • Veo 3.1 — Cinematic quality cao nhất, có audio. Yếu: đắt, chậm, less control.
  • Seedance 2.0 — Dance/body motion tốt. Yếu: face drift ở clips dài.
  • Runway Gen-4 — Style consistency, artistic. Yếu: realistic faces.
  • Kling O1 — Edit video (thay bg, style transfer). Unique capability.
Trong TVC production: Kling 3.0 cho camera moves (orbit, pull-back). Kling O1 cho transform (replace bg). Veo cho high-quality hero shot.
Prompt Engineering — Nguyên tắc core
Tại sao cùng ý mà prompt khác nhau ra kết quả khác nhau
Production

Nguyên tắc

  • Specific > Generic — "woman in blue" (bad) vs "40-year-old East Asian woman in light blue sailor collar dress" (good)
  • Structure matters — Model chú ý đầu prompt nhất. Đặt thứ quan trọng nhất lên đầu.
  • Negative prompt — Nói model KHÔNG làm gì. Bổ sung, không thay thế prompt chính.
  • Natural language > keyword — "cinematic, 4K, masterpiece" đang chết. Mô tả scene như brief DP.

Production-specific

  • Camera movement prompt: đặt riêng, rõ ràng ("Camera steadily pulls back")
  • Duration: match complexity. 5s = 1 action đơn. 7-10s = 2 actions hoặc camera move phức tạp.
  • Đừng prompt quá nhiều thứ cùng lúc → model "chia attention" → không cái nào tốt
Ví dụ: 1 action rõ (đứng→ngồi→đeo giày), static camera, 5s. Simple = AI handle tốt hơn.

Agentic AI

AI không chỉ trả lời — mà tự hành động, dùng tools, lên kế hoạch. Đây là tương lai gần nhất.

AI Agent — Khái niệm cơ bản
Từ "chatbot trả lời" → "AI tự hành động"
Agentic

Chatbot vs Agent

  • Chatbot — Bạn hỏi → nó trả lời. Hỏi tiếp → trả lời tiếp. Passive.
  • Agent — Bạn giao MỤC TIÊU → nó tự lên kế hoạch, dùng tools, xử lý lỗi, hoàn thành. Active.

Ví dụ cụ thể

  • ChatGPT (chatbot): "Viết prompt cho Kling" → viết prompt → xong.
  • Claw (agent): "Gen character sheet Film 4" → upload ref → gen 7 tấm → poll status → download → QC → report. Tự chạy chuỗi actions.
Chatbot = assistant ngồi chờ bạn nói. Agent = producer assistant bạn giao brief rồi đi meeting, quay lại đã có deliverables.

Thành phần của Agent

  • LLM (Brain) — Suy nghĩ, lên kế hoạch
  • Tools — Các "tay chân" (đọc file, chạy code, gọi API, gửi message)
  • Memory — Nhớ context qua sessions (MEMORY.md, daily logs)
  • Planning — Tự chia task lớn thành steps nhỏ
Một AI agent production có thể = LLM + tools (gen ảnh/video, gửi message, quản lý file) + persistent memory. Tự chạy pipeline, hỏi khi cần duyệt.
MCP — Model Context Protocol
Chuẩn giao tiếp cho AI agents dùng tools bên ngoài
Agentic

Bản chất

MCP = giao thức chuẩn (standard protocol) để AI agent "cắm vào" bất kỳ tool/service nào. Anthropic tạo ra, đang trở thành industry standard.

USB cho AI. Trước đây mỗi device cần cable riêng. USB = 1 chuẩn cho tất cả. MCP = 1 chuẩn để AI nói chuyện với mọi service (Higgsfield, Slack, GitHub, databases...).

Cách hoạt động

  • MCP Server — Service cung cấp tools (Higgsfield expose generate_image, generate_video, etc.)
  • MCP Client — AI agent gọi tools đó (Claw gọi Higgsfield qua MCP)
  • Protocol — JSON-RPC 2.0 (format tin nhắn chuẩn giữa client↔server)

Tại sao quan trọng

  • AI agent có thể dùng BẤT KỲ service nào có MCP server — không cần custom code mỗi integration
  • Higgsfield, Figma, GitHub, Slack, databases... đều có/đang build MCP server
  • Tương lai: 1 agent quản lý toàn bộ production pipeline qua MCP
AI agent gọi MCP của platform gen video → submit job → poll status → download kết quả. Không cần mở web UI. Nhưng MCP thường có ít options hơn web.
Coding Agents — Cursor, OpenClaw, Codex
AI tự viết code, tự debug, tự ship — developer-in-a-box
Agentic

Coding Agent là gì

AI agent chuyên viết/sửa code. Không chỉ "gợi ý" (autocomplete) mà tự: đọc codebase → hiểu → plan → viết → test → fix bugs → commit.

Các tools phổ biến

  • Cursor — IDE (editor giống VS Code) + AI agent tích hợp. Bạn mô tả feature → nó code + tạo files + sửa bugs. Phổ biến nhất hiện tại cho developers.
  • OpenClaw (Claw) — CLI agent chạy terminal. Có tools: đọc/viết file, chạy shell, browser, messaging. Versatile hơn — không chỉ code mà quản lý cả workflow.
  • Codex (OpenAI) — Cloud-based coding agent. Chạy tasks trên cloud, trả kết quả. Mới ra.
  • Devin — "AI software engineer" — tự clone repo, viết code, tạo PR. Đắt, controversial.
Trước: EP thuê developer build tool → 2 tuần + $5K. Giờ: mô tả cho coding agent → build trong 1-2 giờ. EP có thể tự build internal tools mà không cần biết code.

Tại sao EP nên biết

  • Build internal tools nhanh (custom prompt generators, QC checkers)
  • Không cần hire developer cho prototype/MVP
  • Biết capability → brief đúng khi giao cho tech team
Coding agent có thể build internal tools (prompt generators, QC checkers, training decks) trong vài giờ thay vì thuê dev vài tuần.
Hermes, OpenHermes, NousResearch
Open-source fine-tuned models cho agent tasks
Agentic

Context

NousResearch = lab tạo ra các model open-weight fine-tuned cho agent use cases. Hermes = tên series model của họ.

Tại sao thấy nhiều người nói

  • Hermes models được train đặc biệt cho function calling (gọi tools) và structured output (trả JSON chuẩn)
  • Open weight → ai cũng chạy được → community lớn
  • Dùng làm "brain" cho agent tự build (thay vì trả tiền GPT-4/Claude)

EP cần biết gì

Không cần dùng trực tiếp. Chỉ cần biết: khi ai đó nói "chạy Hermes agent" = họ đang dùng open-source model (miễn phí, tự host) thay vì trả tiền cho OpenAI/Anthropic. Trade-off: rẻ hơn nhưng thường kém hơn GPT-4/Claude.

Claude/GPT = thuê DP hàng đầu (đắt, consistent). Hermes = DP freelance tốt (rẻ hơn nhiều, đủ dùng cho nhiều tasks, nhưng cần monitor quality hơn).
Agentic Workflow Patterns
Cách agents phối hợp — single vs multi-agent
Agentic

Patterns

  • Single Agent — 1 agent + nhiều tools. Đơn giản, dễ debug. (Claw = single agent dùng nhiều tools)
  • Multi-Agent — Nhiều agents chuyên biệt, 1 "orchestrator" phân công. Phức tạp, mạnh hơn cho tasks lớn.
  • Human-in-the-loop — Agent chạy nhưng cần human approve ở bước quan trọng. (Claw hỏi Nam duyệt trước khi gen paid credits)
  • Autonomous — Agent chạy tự do không cần approve. Nguy hiểm hơn nhưng nhanh hơn.
Single agent = 1 producer senior handle all. Multi-agent = EP + Line Producer + Post Sup + Production Manager — mỗi người 1 domain, EP orchestrate.

Ví dụ Multi-Agent trong production

  • Agent 1 (Claw/Main): Plan + brief + QC
  • Agent 2 (GenWorker): Chạy gen image/video + poll results
  • Agent 3 (Seegroup Bot): Handle external queries + team comms
  • Orchestrator: Main session phân công task cho sub-agents
RAG — Retrieval-Augmented Generation
Cách cho AI "kiến thức mới" mà không cần train lại
Agentic

Bản chất

LLM chỉ biết những gì được train (đến ngày X). Muốn nó biết thêm (data công ty, documents mới) → 2 cách:

  • Fine-tune — Train thêm data vào model. Đắt, chậm, cần expertise.
  • RAG — KHÔNG train. Thay vào đó: search database/documents → lấy phần liên quan → nhét vào prompt → model đọc + trả lời. Rẻ, nhanh, update realtime.
Fine-tune = gửi DP đi học workshop 1 tháng. RAG = đưa DP cuốn sách reference trước mỗi buổi quay — DP đọc nhanh rồi apply. Không cần học thuộc, chỉ cần đọc đúng lúc.

Áp dụng thực tế

  • Claw đọc MEMORY.md + memory/*.md trước khi trả lời = dạng RAG (retrieval from files)
  • Seegroup Bot đọc skills + research = RAG
  • Chatbot có "upload documents" rồi hỏi đáp = RAG
AI assistant đọc project files mỗi session → biết context dự án, quy tắc, bài học. Không train lại model — chỉ đọc tài liệu. Đó là RAG.

Infrastructure, deployment, cách AI chạy trong thực tế — từ cloud đến local.

Local vs Cloud vs Edge
AI chạy ở đâu — và tại sao quan trọng
Ops

3 nơi AI chạy

  • Cloud — Chạy trên server xa (AWS, Google Cloud). Mạnh nhất, đắt nhất. GPT-4, Claude, Kling đều cloud.
  • Local — Chạy trên máy mình. Miễn phí sau setup, riêng tư, offline. Cần GPU mạnh. Ví dụ: Ollama chạy LLaMA trên MacBook.
  • Edge — Chạy trên device nhỏ (phone, IoT). Nhanh, offline, nhưng model nhỏ → kém hơn. Ví dụ: Apple Intelligence, on-device Gemini Nano.

Tại sao EP cần biết

  • Cloud = tốn credit/tiền mỗi lần dùng. Scale dễ nhưng phụ thuộc internet.
  • Local = đầu tư hardware 1 lần, chạy không giới hạn. Nhưng cần GPU $2K-$10K.
  • Hybrid: dùng local cho tasks lặp (draft, test) → cloud cho final quality (Kling Pro, Veo).
AI assistant chạy cloud (API). Gen ảnh/video = cloud. Nếu có GPU local → chạy FLUX locally = unlimited gen, không tốn credit.
GPU & VRAM — Tại sao AI cần card đồ họa
Phần cứng quyết định model nào chạy được
Ops

Bản chất

  • GPU (Graphics Processing Unit) — Xử lý song song hàng ngàn phép tính cùng lúc. AI cần tính toán ma trận khổng lồ → GPU nhanh hơn CPU 10-100x cho tasks này.
  • VRAM — RAM trên GPU. Model càng lớn → cần càng nhiều VRAM. GPT-4 cần hàng trăm GB VRAM (chỉ datacenter). FLUX cần ~12-24GB (PC high-end).
  • NVIDIA — Thống trị thị trường AI GPU. RTX 4090 (24GB) = consumer tốt nhất. H100/A100 = datacenter.
GPU = rendering farm cho CG. Cũng là lý do render farm tốn tiền — GPU mạnh = đắt. AI inference = real-time rendering.

Mức VRAM cần

  • 8GB — Chạy model nhỏ (7B params). Chat OK, gen ảnh basic.
  • 12-16GB — Chạy FLUX local, model 13B. Decent quality.
  • 24GB (RTX 4090) — Chạy hầu hết open-weight models. Sweet spot cho local AI.
  • 48-80GB+ — Datacenter. Train models, run multiple large models.

Không cần dùng. Chỉ biết: khi dev nói "deploy bằng Docker" = đóng gói app chạy trên server. Khi nghe "containerized" = app được đóng gói chuẩn, dễ scale.

Deep Dive — Bên trong AI

Đào sâu hơn vào bản chất hoạt động — hiểu TẠI SAO AI làm được (và không làm được) những gì nó làm.

Latent Space — Không gian ẩn
Nơi AI "suy nghĩ" — tại sao nó có thể morph, interpolate, mix style
Deep Dive

Bản chất

Ảnh 1024×1024 = 1 triệu pixel — quá lớn để xử lý. Nên AI nén thành "latent" nhỏ hơn (64×64), giữ lại "bản chất" — rồi làm việc trên bản nén đó. Xong thì giải nén ra ảnh đầy đủ.

Encoder = tóm tắt brief (50 trang → 2 trang key points). Decoder = triển khai brief (2 trang → storyboard đầy đủ). AI suy nghĩ bằng brief 2 trang, không phải 50 trang.

Tại sao quan trọng

  • Tốc độ: Làm việc trên latent nhỏ nhanh hơn 100x so với pixel
  • Interpolation: Di chuyển từ điểm A→B trong latent = morph mượt giữa 2 ảnh. Đó là cơ sở video gen
  • img2img giữ mặt tốt hơn: Bắt đầu từ latent CỦA ẢNH GỐC (đã có identity) thay vì noise random
  • Style mixing: "Monet" và "Cyberpunk" = 2 vùng trong latent space. Đi giữa = style hybrid
Video Generation — Tại sao khó hơn Image
Temporal consistency, interpolation trap, và motion physics
Deep Dive

2 cách gen video

  • Temporal Diffusion: Gen từng frame nhưng có "temporal attention" — mỗi frame "nhìn" frame trước+sau. Kling, Runway dùng cách này.
  • Autoregressive: Gen frame 1 → dựa frame 1 gen frame 2 → frame 3... Consistent hơn nhưng chậm.
Temporal diffusion = quay multi-cam rồi sync bằng timecode. Autoregressive = quay single-cam liên tục — frame sau phụ thuộc frame trước.

Tại sao video gen khó hơn

  • 5 giây video = 120 ảnh phải giống nhau — image chỉ cần 1
  • Physics: Tóc bay, vải rủ phải tuân vật lý
  • Interpolation trap: Start frame pose A + End frame pose B → AI BUỘC tay di chuyển dù prompt nói "freeze"
  • Face drift: Clip dài > 5s → mặt dần thay đổi

Production rules

  • Start + End frame phải cùng pose nếu muốn body static
  • 5s = 1 action. Đừng nhồi nhiều action
  • Camera move HOẶC subject move — không cả 2 cùng lúc
LoRA & Embeddings — Customize AI không tốn $$
Cách dạy AI nhận diện mặt, học style mới bằng chi phí thấp
Deep Dive

LoRA (Low-Rank Adaptation)

Thay vì train lại toàn bộ model (tỷ tham số, tốn $$$), chỉ thêm 1 "lớp mỏng" adapter lên trên. File nhỏ (10-200MB), train trong phút-giờ, GPU consumer chạy được.

LoRA = lens filter cho camera. Camera (model) giữ nguyên, chỉ đeo thêm filter để đổi look. Tháo filter = quay lại default. Đeo filter khác = look khác.

Embeddings

Biến mọi thứ (từ, ảnh, concept) thành 1 dãy số. Thứ giống nhau → số gần nhau. Đó là cách AI "biết" 2 ảnh có vibe giống nhau dù mô tả text khác.

Embedding = thẻ tag thông minh cho mỗi asset. Thay vì tag thủ công "outdoor, sunset" — AI tự tạo tag dạng số. 2 ảnh có vibe giống → tag số gần nhau, dù text khác.

Ứng dụng thực tế

  • Face LoRA: Train mặt nhân vật → giữ consistent qua nhiều ảnh
  • Style LoRA: Áp film grain, color palette cụ thể
  • Soul ID (Higgsfield): Bản chất là LoRA-like — train mặt từ 5-15 ảnh
  • RAG (search): Dùng embeddings tìm tài liệu liên quan trong database
Attention Mechanism — Tại sao prompt structure quan trọng
Model "chú ý" có giới hạn — biết để prompt tốt hơn
Deep Dive

Cách attention hoạt động

Transformer nhìn MỌI CẶP TỪ cùng lúc và tính: "từ A quan trọng bao nhiêu với từ B?" Prompt "cô gái mặc áo xanh cầm phone" → model biết "áo xanh" thuộc "cô gái", "phone" liên quan "cầm".

Attention = đạo diễn xem rushes. Thay vì xem tuần tự clip 1→2→3, đạo diễn nhìn tất cả clips trên bàn cùng lúc và thấy connections: "clip 3 nối clip 7 vì cùng location."

Prompt rules từ attention

  • Đầu prompt = attention cao nhất. Đặt thứ quan trọng nhất lên đầu
  • Cuối prompt = quan trọng thứ 2. Chi tiết bổ sung
  • Giữa prompt = ít attention nhất. Dễ bị bỏ qua
  • Prompt quá dài = chia mỏng attention. 200 từ → không cái nào tốt. Ngắn + rõ = tốt hơn
Multimodal — 1 model hiểu mọi thứ
Tại sao GPT-4o vừa đọc text, vừa nhìn ảnh, vừa nghe audio
Deep Dive

Bí quyết

Biến MỌI loại input thành cùng 1 format: tokens. Text → tokens. Ảnh → chia thành patches → tokens. Audio → chuyển sóng âm → tokens. Tất cả vào cùng 1 transformer xử lý chung.

Multimodal = EP xem rushes. EP nhìn hình (image), đọc script (text), nghe guide track (audio) → hiểu tổng thể scene. Mọi thứ encode thành 1 ngôn ngữ chung: "storytelling."

Tại sao thay đổi production

  • Upload board → AI phân tích (không cần describe bằng text)
  • Reference image + prompt = output tốt hơn pure text
  • QC tự động: AI nhìn output → đánh giá → suggest fix
  • Tương lai: Upload storyboard + brief → AI output pre-vis video
Agent Orchestration — Điều phối nhiều AI
Multi-agent, human-in-the-loop, và tương lai AI Studio
Deep Dive

3 patterns

  • Single agent: 1 brain + nhiều tools. Đơn giản, dễ debug. Phổ biến nhất hiện tại
  • Multi-agent: Nhiều agents chuyên biệt, 1 orchestrator phân công. Mạnh hơn cho tasks lớn
  • Human-in-the-loop: Agent chạy nhưng dừng hỏi ở bước quan trọng (duyệt credit, approve output)
Single agent = 1 producer senior handle all. Multi-agent = EP + Line Producer + Post Sup + PM — mỗi người 1 domain, EP orchestrate. Human-in-the-loop = client approval gate.

Tương lai AI Studio

  • Agent 1 nhận brief + phân tích board
  • Agent 2 gen image/video batch
  • Agent 3 QC output
  • Agent 4 delivery + client comms

Đọc hiểu Model Updates

Mỗi khi hãng AI ra model mới, bài so sánh toàn thuật ngữ — đây là cách đọc hiểu.

Benchmark — Bảng điểm AI
SWE-bench, ARC, MMLU, OSWorld... mỗi cái đo gì, số nào là tốt
Model Updates

Benchmark là gì

Bài kiểm tra chuẩn hóa cho AI — giống SAT, IELTS nhưng cho model. Mỗi benchmark đo 1 kỹ năng cụ thể. Hãng nào ra model mới cũng chạy benchmark rồi khoe điểm.

Benchmark = KPI đánh giá nhân viên. Bạn không thuê người chỉ vì "giỏi" — bạn hỏi: "giỏi cái gì? sales? quản lý? sáng tạo?" Benchmark cho AI cũng vậy — mỗi bài đo 1 năng lực khác nhau.

Các benchmark quan trọng nhất (2026)

  • SWE-bench Verified — Đo khả năng code. Cho AI 1 bug thật trên GitHub → tự sửa. 80%+ = rất giỏi. 87%+ = top thế giới.
  • ARC AGI 2 — Đo suy luận mới (novel reasoning). Bài toán AI chưa bao giờ thấy → test tư duy thật sự, không phải nhớ. 70%+ = breakthrough.
  • MMLU — Kiến thức tổng hợp 57 chủ đề (lịch sử, khoa học, luật...). 90%+ = frontier.
  • GPQA Diamond — Câu hỏi PhD-level (vật lý, hóa, sinh). 90%+ = rất mạnh.
  • OSWorld — AI tự dùng máy tính (click, gõ, navigate GUI). 70%+ = production-ready.
  • MCP Atlas — Phối hợp nhiều tools cùng lúc. Quan trọng cho AI agents. 75%+ = tốt.
  • HumanEval / MATH — Code + toán. Cổ điển nhưng vẫn dùng nhiều.

Cách đọc benchmark

  • Số % cao hơn = tốt hơn (đơn giản vậy thôi)
  • +2-3% = cải tiến nhỏ (incremental). +7-10% = nhảy lớn (significant). +30%+ = bước ngoặt (breakthrough)
  • So sánh cùng benchmark, cùng điều kiện — đừng so SWE-bench model A với MMLU model B
  • Benchmark ≠ thực tế 100% — model điểm cao vẫn có thể fail use case cụ thể của bạn
Đừng thuê nhân viên chỉ vì CV đẹp. Benchmark là CV — hữu ích để lọc, nhưng cuối cùng phải test thử với công việc thật của mình.
Tokenizer — Tại sao model mới "tốn" thêm tokens
Cùng câu hỏi, model mới có thể tính nhiều tokens hơn — ảnh hưởng giá
Model Updates

Tokenizer là gì

Bộ "cắt từ" của AI. Trước khi đọc câu, AI phải cắt text thành mảnh nhỏ (tokens). Mỗi model có cách cắt khác nhau.

  • "Xin chào bạn" → Model A cắt: [Xin] [chào] [bạn] = 3 tokens
  • "Xin chào bạn" → Model B cắt: [Xin] [ch] [ào] [bạn] = 4 tokens
  • Cùng câu, model B tốn nhiều tokens hơn → tốn tiền hơn
Tokenizer = cách tính giờ công. Cùng 1 task, công ty A tính 8 man-hours, công ty B tính 10 man-hours. Đơn giá/giờ giống nhau nhưng tổng bill khác nhau. Khi vendor đổi cách tính → kiểm tra lại tổng chi phí.

Khi nào cần quan tâm

  • Model mới nói "new tokenizer" → kiểm tra xem token count tăng bao nhiêu %
  • Ví dụ: Claude Opus 4.7 dùng tokenizer v2 → tốn thêm 0-35% tokens so với 4.6
  • Giá/token không đổi nhưng cùng prompt → tổng bill cao hơn
  • Nếu dùng ít (vài chục USD/tháng) → không đáng lo. Nếu dùng nhiều ($1000+/tháng) → cần tính lại
Thinking Modes — AI "suy nghĩ" trước khi trả lời
Extended Thinking → Adaptive Thinking → Effort Levels — đang tiến hóa thế nào
Model Updates

Vấn đề gốc

AI trả lời ngay lập tức → hay sai với bài khó. Giải pháp: cho AI thời gian "suy nghĩ" trước khi trả lời — giống người cần thời gian phân tích vấn đề phức tạp.

Tiến hóa

  • Extended Thinking (cũ) — Bạn set thủ công: "cho AI suy nghĩ tối đa 32K tokens". Cứng nhắc — task dễ cũng tốn nhiều, task khó thì thiếu.
  • Adaptive Thinking (hiện tại) — AI tự quyết định suy nghĩ bao nhiêu tùy độ khó. Bạn chỉ chọn "effort level".
  • Effort Levels — low / medium / high / xhigh. Cao hơn = suy nghĩ nhiều hơn = chính xác hơn = chậm + tốn hơn.
Extended Thinking = set deadline 1 tuần cho MỌI task, dù lớn hay nhỏ. Adaptive Thinking = để nhân viên tự đánh giá task cần bao lâu. Effort level = bạn nói "cái này cần kỹ" (high) hay "nhanh thôi không cần hoàn hảo" (low). Quản lý tốt hơn là cho nhân viên linh hoạt, chỉ set kỳ vọng.

Thực tế

  • Hỏi nhanh (dịch, tóm tắt) → low/medium, trả lời nhanh rẻ
  • Phân tích phức tạp (chiến lược, debug) → high/xhigh, chậm nhưng chất lượng
  • Khi đọc "Extended Thinking removed" = tính năng cũ bị bỏ, chuyển sang Adaptive tốt hơn
Context Window — Thực tế 200K vs 1M
Con số trên giấy vs thực tế dùng — và tại sao "dài hơn" chưa chắc tốt hơn
Model Updates

Quy đổi thực tế

  • 200K tokens ≈ 150K từ ≈ 300 trang sách ≈ 1 cuốn tiểu thuyết
  • 1M tokens ≈ 750K từ ≈ 1500 trang ≈ 5 cuốn tiểu thuyết cùng lúc

Nhưng...

  • Dài hơn ≠ tốt hơn tuyệt đối. Model "nhìn" 1M tokens nhưng "chú ý" đều ở mọi điểm thì cần model rất mạnh
  • "Lost in the middle" — Model hay chú ý đầu + cuối, bỏ qua giữa. Đang cải thiện dần (4.6 tốt hơn hẳn 4.5)
  • Tokens nhiều = tốn tiền. Nhét 1M tokens input = $5 MỖI câu hỏi (với Opus). Dùng thông minh.
Context window = sức chứa phòng họp. Phòng 10 người (200K) vs sân vận động 50K người (1M). Phòng lớn hơn chưa chắc tốt hơn — nếu bạn chỉ cần meeting 5 người, booking sân vận động vừa tốn vừa khó tập trung. Chọn phòng đúng size.

Khi nào cần 1M tokens?

  • Review toàn bộ codebase 1 lần
  • Phân tích hợp đồng/tài liệu dài (>100 trang)
  • Context conversation rất dài (agent chạy hàng giờ)

Hầu hết use case thông thường: 200K đã quá đủ.

Breaking Changes — Khi model mới "phá" code cũ
Đọc changelog biết cái nào ảnh hưởng mình, cái nào bỏ qua
Model Updates

Breaking change là gì

Thay đổi khiến code/workflow cũ KHÔNG CHẠY được nữa. Phân biệt với "behavior change" = chạy được nhưng kết quả khác.

Breaking change = nhà cung cấp đổi quy cách đóng gói. Trước giao hàng bằng pallet chuẩn, giờ đổi sang kiện mới — xe tải cũ không chở vừa. Phải đổi xe (update code) hoặc yêu cầu giao kiểu cũ (nếu còn support).

Ví dụ thật (Claude Opus 4.7)

  • "temperature removed" → Nếu bạn chỉ dùng web/app chat = không ảnh hưởng. Nếu gọi API có set temperature = code sẽ lỗi 400.
  • "Extended Thinking removed" → Code cũ dùng Extended Thinking phải đổi sang Adaptive.
  • "New tokenizer" → Code vẫn chạy nhưng tốn thêm tokens → bill cao hơn.

Ai cần đọc breaking changes?

  • Dùng web chat (ChatGPT, Claude.ai) → Hầu như không ảnh hưởng
  • Dùng API / có dev team → PHẢI đọc, test trước khi upgrade
  • Dùng tool build trên API (Claw, Cursor...) → Tool vendor lo, nhưng biết để debug nếu lỗi

Model "nhìn" ảnh thế nào

Gửi ảnh cho AI → nó resize xuống giới hạn max → xử lý. Ảnh 4K gửi cho model 1568px max → bị nén xuống → mất chi tiết nhỏ.

  • 1568px (cũ) — ~1.15 megapixels. Nhìn OK tổng thể nhưng text nhỏ, icon, chi tiết = mờ
  • 2576px (mới) — ~3.75 megapixels (3.3x). Đọc được text nhỏ, phân biệt icon, thấy chi tiết
Như upgrade camera giám sát từ SD lên Full HD. Trước chỉ thấy "có người đi qua". Giờ thấy rõ mặt, đọc được biển số. Cùng hệ thống, chỉ đổi "mắt" — nhưng thông tin thu được khác hẳn.

Ảnh hưởng thực tế

  • AI đọc document/screenshot → chính xác hơn, ít miss text nhỏ
  • Computer use (AI dùng máy tính) → click đúng icon hơn, đọc UI rõ hơn
  • QC output AI video → AI nhìn frame chi tiết hơn, phát hiện lỗi nhỏ
  • Trade-off: Ảnh rõ hơn = tốn nhiều tokens hơn → tốn tiền hơn
